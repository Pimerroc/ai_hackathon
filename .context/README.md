# `.context` — рабочая память проекта

Этот каталог — краткая, структурированная память для команды и coding-агентов. Он не заменяет GitLab issues, а даёт контекст, который дорого восстанавливать из переписки.

## Порядок чтения

1. `../AGENTS.md` — правила и границы.
2. `product.md` — что и для кого строим.
3. `architecture.md` — компоненты, поток данных, agent loop.
4. `team.md` — роли, RACI, handoff-контракты.
5. `workflow.md` — GitLab, milestones, labels, MR, DoR/DoD.
6. `llm.md` — base URL, модели, бюджет, безопасность.
7. `data.md` — данные, профиль компании, граф, RAG.
8. `api.md` — endpoints, insight schema, tools.
9. `quality.md` — тесты, eval, CI, ZIP verification.
10. `demo.md` — сценарии, демо-скрипт, fallback.
11. `issue-map.md` — 30 дневных issues + мастер-эпик #54.
12. `decisions.md` — принятые решения и ADR.
13. `current-state.md` — что уже есть и что делать дальше.

## Правила обновления

- Обновляй `.context` тем же MR, который меняет поведение.
- Не дублируй длинные issue-описания: здесь — принципы и ссылки.
- Секреты, ключи, реальные PII и токены сюда не пишем.
- Если решение меняет архитектуру, добавь запись в `decisions.md`.
- Если меняется контракт, обнови `api.md` и `contracts/` в одном MR.

## Статус

Каталог создан 21.10.2026 как стартовый контекст. По мере появления кода дополняй конкретными командами, путями и схемами.
