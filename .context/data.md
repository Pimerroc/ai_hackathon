# Данные

## Источники

| Источник | Формат | Что даёт |
|---|---|---|
| Компании ЮЛ | CSV | профиль, ОКВЭД, выручка, регион, возраст, работники, ФТС, negative mark |
| Физлица | CSV | связанные лица, группа |
| Платежи | CSV | контрагенты, обороты, направления |
| Аналитика Альфа-Банка | 9 PDF | отраслевые обзоры, позиция банка |
| Новости | RSS/HTML | внешние события |
| Alfa-Business / кейс | web/PDF | продуктовый и UX-контекст |

## Профиль компании

Минимальный набор для персонализации:

- `client_id`, название, ИНН/ОГРН (если есть), группа;
- ОКВЭД/отрасль, основной вид деятельности;
- выручка и revenue percentile в отрасли/портфеле;
- регион, возраст компании, число работников;
- продукты банка: кредиты, гарантии, факторинг, эквайринг, зарплатный проект, ВЭД;
- ФТС/внешнеэкономическая активность;
- negative mark / проблемность;
- групповые связи и общие физлица;
- контрагенты по платежам.

Если доли рынка нет — используем proxy: выручка компании / сумма выручки отрасли в портфеле, с пометкой «оценка».

## Граф

- `company -> group` по `GROUP_ID`;
- `company -> person` по общим ФЛ;
- `company -> counterparty` по платежам;
- `company -> region/industry`.

Для MVP достаточно basic graph. Advanced graph (2–3 уровня, веса связей, визуализация) — P1 и режется первым.

## Новости

Схема:

```json
{
  "id": "",
  "title": "",
  "url": "",
  "source": "",
  "published_at": "",
  "language": "ru",
  "entities": [{"type": "company|person|region|industry", "name": "", "id": ""}],
  "event_type": "regulation|rate|sanctions|logistics|contract|market|other",
  "geo": [],
  "quality_score": 0.0,
  "content": "",
  "content_hash": ""
}
```

Дедуп: URL + content hash + MinHash/эмбеддинги. Дубликаты < 5%.

## PDF Альфа-Банка

Chunk metadata:

- `document_id`, `title`, `published_at`;
- `page`, `section`, `topic`;
- `text`, `tokens`, `embedding`;
- `quote` — точная цитата для UI;
- `language`.

Требование: цитата должна быть verbatim; нельзя пересказывать «позицию банка» без источника.

## Хранение

- Postgres + pgvector.
- Raw данные — отдельно от нормализованных.
- `events` — значимые события; `insights` — интерпретация; `evidence` — связь тезиса с источником.
- `agent_runs`, `agent_steps`, `tool_calls` — trace.
- `feedback` — оценка пользователя.
- `audit_log` — доступ и действия.

## Качество и ограничения

- Данные могут быть неполными, неоднозначными, зашумлёнными.
- Не выдумывать отсутствующие поля; показывать confidence и «недостаточно данных».
- Конфликт источников показывать явно.
- Реальные PII в демо не нужны; используем seed/маскирование.
- Synthetic fallback — только для демо и тестов, с пометкой.

## Seed

- 3 демо-персоны: металлоэкспортёр, ритейлер-импортёр, строительная группа.
- 50+ новостей, 9 PDF, профили, группа, контрагенты.
- Demo-аккаунты и reset script.
- Offline demo data для `DEMO_MODE=1`.

## Ranking signals

- semantic similarity;
- entity match (компания, группа, контрагент);
- graph proximity;
- product exposure (кредиты/валюта/ВЭД/логистика);
- region/industry match;
- revenue scale;
- event type и impact;
- recency и source quality;
- bank coverage;
- feedback пользователя.

## Приватность

- Не коммитить реальные CSV/PDF, если они содержат PII.
- Для публичного репозитория — только синтетические/обезличенные фикстуры.
- В ZIP — только разрешённые демо-данные.
- Логи не должны содержать полные prompt’ы и персональные данные.
